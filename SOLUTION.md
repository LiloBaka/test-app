## Решения

<!-- Куда отнесли матчи с другими статусами и почему. Какие ещё неочевидные случаи нашли в данных и как обработали. -->

«Предстоящие» содержит только scheduled, «Завершённые» — только finished. live, postponed и неизвестные статусы остаются во «Все»: они не относятся к двум специальным фильтрам. Источник статуса — API, а не текущая дата.

Счёт проверяется на null, поэтому 0:0 не теряется. Без счёта выводится «—», без даты — «Дата уточняется». Intl.DateTimeFormat переводит UTC в часовой пояс устройства без фиксированного смещения. Некорректная дата отклоняется валидатором API; форматирование дополнительно защищено от неё. Неизвестный статус отображается как «Статус уточняется», для live показывается минута, если она есть, включая 0. Минуты других статусов не показываются.

Данные JSON принимаются как unknown и проверяются во время выполнения. Некорректная структура, повторяющиеся ID, HTTP-ошибка и невалидный JSON приводят к сообщению с повторной попыткой. Локальный JSON не используется как источник данных приложения.

Избранное хранится единым массивом ID в useFavorites на уровне MatchesScreen. Смена фильтра и обновление данных не пересоздают этот state; FavoriteButton получает active и обработчик из экрана. FlatList получает favorites через extraData, чтобы учитывать изменение избранного.

В качестве дополнительного улучшения выбран поиск по клубу: он помогает найти нужный матч и не требует новых зависимостей. Запрос обрезается по краям и приводится к нижнему регистру, затем проверяется в названиях обеих команд; условие поиска применяется одновременно с фильтром статуса. Пустой запрос возвращает все матчи выбранного статуса. Поиск выполняется по уже загруженному списку, не создаёт сетевых запросов и не сбрасывает избранное.

## Баги из части 2



1. Звёздочки: indexOf возвращает -1 для отсутствующего ID и 0 для первого элемента; Boolean превращал их соответственно в true и false. Кроме того, push/splice мутировали массив React state, а setFavorites получал прежнюю ссылку: при ссылочном равенстве по Object.is React мог пропустить обновление. Проверка заменена на includes, а toggle использует функциональный setFavorites с filter или новым массивом через spread, поэтому учитывает очередь обновлений и не меняет предыдущий state.
2. «Обновлено N сек назад»: эффект с пустыми зависимостями захватывал seconds = 0, поэтому замыкание каждый раз вызывало setSeconds(1); since игнорировался, а интервал не очищался. Теперь каждый тик вычисляет Math.max(0, Math.floor((Date.now() - sinceMs) / 1000)), эффект зависит от числового sinceMs и сразу обновляет подпись при его смене. Возвращаемая из эффекта функция вызывает clearInterval: React очищает старую подписку перед новой и при размонтировании, а новый объект Date с тем же временем не перезапускает интервал.
